# 02 · 相册功能完整规格

> 本文给出相册模块的功能规格。凡与 `05-change-log.md` 的 FINAL 条目冲突处，以 change-log 为准。  
> 本文按迭代阶段组织（阶段一 = 基础相册，阶段二 = 封面与排序，阶段三 = 批量操作），但**所有规则一次性长期生效**，后续阶段默认继承之前全部规则。

## 阶段一：基础相册（CRUD + 成员关系）

### 2.1 相册实体

一个相册至少包含：

- `id`：主键。
- `name`：相册名，必填，去除首尾空白后不能为空，长度 1~50 字符；同名相册是否允许见 2.6。
- `description`：可选简介，最长 200 字符。
- `coverPictureId`：封面图片 id，可为空（空时按 2.8 的回退规则计算展示封面）。
- `pictureCount`：相册内图片数量（可为持久字段或实时统计，见 03 文档，但对外一定要返回准确值）。
- `createTime` / `updateTime`：创建与最近更新时间。

### 2.2 成员关系（Membership）

- 图片与相册是**多对多**关系（呼应 HD-2）。实现上应有独立的关联结构（关联表或关联实体），**不得**在 `Picture` 上加单一 `albumId`，也**不得**复制图片记录。
- 同一张图片在同一相册中**至多出现一次**（重复加入应被忽略，不报错，见阶段三）。
- 同一张图片可以出现在任意多个不同相册中。

### 2.3 新建相册

- 输入 `name`（必填）、`description`（可选）。
- 新建时相册为空，无封面，`pictureCount = 0`。

### 2.4 重命名 / 编辑相册

- 可修改 `name` 与 `description`，校验规则同 2.1。
- 重命名不影响成员关系与封面。

### 2.5 删除相册（重点，呼应 HD-1）

- 删除相册**只删除该相册本身及其成员关系记录**。
- **绝对不能**删除任何图片文件，也不能删除任何 `Picture` 记录。
- 删除相册后，被包含过的图片仍完整存在于图库，且若它还属于别的相册，那些相册不受影响。

### 2.6 命名冲突策略

- 允许不同相册重名（因为相册以 id 标识）。但前端在创建/重命名时**应给出重名提示**，交由用户确认。后端不因重名而拒绝。
- （历史插曲，DEPRECATED）早期曾要求"相册名全局唯一，重名直接 409 拒绝"，该规则已被放宽，见 change-log CL-4，勿再强制唯一。

### 2.7 加入 / 移出图片

- **加入**：把一张已存在的图片与相册建立成员关系。图片必须已存在于图库；不存在则报错。
- **移出（remove）**：解除某图片与某相册的成员关系。**这只是解除关系，不删除图片本身**（再次呼应 HD-1）。
- 加入 / 移出后，相册的 `pictureCount` 与 `updateTime` 必须及时更新。

### 2.8 相册列表与详情

- **相册列表**：展示每个相册的名称、封面（按 2.9 计算）、图片数量、最近更新时间。
- **相册详情**：仅展示该相册内的图片；这些图片依然是图库里的同一批图片实体（同一 id、同一文件），不是副本。

## 阶段二：封面与排序

### 2.9 封面规则（呼应 HD-3）

- 用户可**手动指定**封面，但指定的图片必须是该相册**当前成员**；若指定非成员图片，报错。
- 若相册**未手动指定**封面（`coverPictureId` 为空），则展示封面 = 相册中**最近加入的成员**。
- **自动回退**：当封面对应图片被移出该相册、或在图库中被删除时，`coverPictureId` 必须失效并回退——回退目标为"当前相册中最近加入的成员"；若相册已空，则无封面。
- 回退必须是自动、即时的，用户不需要手动干预。

### 2.10 相册内排序

- 用户可自定义图片在相册内的显示顺序。
- 顺序需**持久化**：详情刷新、重新进入后顺序保持一致。
- **新加入的图片默认排在最前面**（置顶）。
- 排序是"相册内"的属性：同一张图片在不同相册中的位置互不影响。

### 2.11 封面与排序的关系

- "最近加入"用于两处：默认封面（2.9）与新图默认置顶（2.10）。二者需口径一致，即"最近加入的成员排在最前、并在无手动封面时充当封面"。

## 阶段三：批量操作

### 2.12 批量加入

- 从图库一次选择**多张图片**加入某个相册。
- 其中**已在该相册中的图片应被安全忽略**（不报错、不产生重复成员关系）。
- 批量加入后，新加入的这批图片按 2.10 规则进入排序（整体置顶，组内顺序见 03 文档说明）。

### 2.13 批量移出

- 在某相册中一次移出多张图片，语义等同多次执行 2.7 的"移出"（只解关系，不删图）。
- 若移出的图片中包含当前封面，触发 2.9 的自动回退。

### 2.14 批量请求中的无效项

- 批量请求可能包含**不存在的图片 id 或相册 id**。对这类无效项的处理策略，采用 `03-api-contract.md` 与 `05-change-log.md` 中确定的**「部分成功（partial success）」**策略，不得整单静默失败，也不得因个别无效项而丢弃全部有效操作。具体返回结构见 03 文档。

### 2.15 一致性要求

- 任一批量操作完成后，相册的 `pictureCount`、封面、排序都必须**立即处于一致状态**，前端刷新即可看到正确结果。

## 关于前端体验（跨阶段）

- 所有破坏性操作（删除相册、批量移出）前端必须有**自定义确认弹层**，禁止使用浏览器原生 `window.confirm` / `alert`；批量移出的确认文案需包含选中数量。
- 操作反馈沿用现有 toast 风格，成功 / 失败都要有可读中文提示。
- 视觉风格与现有图库一致，不得为相册单独引入新的组件库或 CSS 框架（详见 `04-engineering-guide.md`）。
