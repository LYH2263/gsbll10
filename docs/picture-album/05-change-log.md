# 05 · 变更日志与最终决议（FINAL 以本文为准）

## CL-1 · 2026-05-06 · 立项评审

- 确认引入"相册（Album）"作为图片之上的逻辑分组能力。
- 确认相册为增量迭代，在现有工程内扩展，沿用现有端口（前端 4140 / 后端 8140 / MySQL 33060）。
- 提出数据安全红线 HD-1。
- 状态：**FINAL（立项基线）**。

## CL-2 · 2026-05-06 · 建模方案第一版（已被推翻）

- 曾提议：在 `Picture` 上加字段 `albumName`（逗号分隔多个相册名）实现分组。
- 否决原因：无法重命名相册、无法维护封面/顺序、检索差、易脏数据、无法真正表达"一图多相册"。
- 状态：**DEPRECATED**。禁止实现 `Picture.albumName` 或任何"逗号分隔相册"的做法。

## CL-3 · 2026-05-13 · 建模方案第二版（已被推翻）

- 曾提议：给 `Picture` 加单一外键 `albumId`（一图一相册）。
- 否决原因：与"一张图可属于多个相册"的核心诉求冲突（见 01 文档用户反馈 B）。
- 状态：**DEPRECATED**。禁止用 `Picture.albumId` 单一外键实现。

## CL-4 · 2026-05-13 · 建模方案最终版

- 采用**独立的多对多成员关系**（关联表 / 关联实体：albumId + pictureId + sortOrder + joinTime）。
- 一张图片可属于多个相册；成员关系记录承载排序与加入时间。
- 相册名**不要求全局唯一**，允许重名（以 id 区分），前端可给重名提示但后端不拒绝——由此放宽了更早"相册名唯一、重名 409"的设想（该设想作废）。
- 状态：**FINAL（数据建模最终决议）**。

## CL-5 · 2026-05-20 · 封面与排序评审

- 封面必须是相册当前成员（HD-3）。
- 手动封面优先；未手动指定时，展示封面 = 相册中"最近加入"的成员。
- 封面对应图片被移出相册或在图库删除后，**自动即时回退**到"当前最近加入的成员"，相册为空则无封面。
- 相册内顺序需持久化；新加入图片默认置顶；顺序是"相册内"属性，跨相册互不影响。
- 早期"封面固定取第一张上传的图、且不随成员变化"的想法（导致灰度期封面乱跳/失效投诉，见 01 用户 D）已废弃。
- 状态：**FINAL（封面与排序最终决议）**。

## CL-6 · 2026-05-27 · 批量操作与错误处理评审（关键）

- 支持批量加入 / 批量移出图片。
- **幂等**：批量加入时已在相册中的图片安全忽略；批量移出时本就不在相册中的图片安全忽略。忽略不算失败。
- **无效项处理采用「部分成功（partial success）」**：有效项照常执行，无效项（图片不存在等）在返回体的 `failed` 中逐项说明原因，**不整单回滚、不静默丢弃**。返回结构见 `03-api-contract.md` §5（requested / succeeded / ignored / failed）。
- 唯一的整单前置失败：**相册 id 本身不存在** → 直接 `code≠0`、`message="相册不存在"`。
- 早期"只要有一个 id 非法就整单 400、不做任何变更"的**全有或全无**策略**已废弃**。
- 状态：**FINAL（批处理策略最终决议）**。

## CL-7 · 2026-05-27 · 删除语义再确认

- 再次确认 HD-1：删除相册 / 移出图片**只动关系，不动图片**；只有图库"删除图片"才物理删除文件与记录。
- 删除相册需连带清理该相册的成员关系记录（避免悬挂关系），但**绝不触碰图片**。
- 状态：**FINAL**。

## CL-8 · 2026-06-03 · 工程纪律复核

- 复核并确认 `04-engineering-guide.md` 全部条目：Java 8 兼容、禁新增前端组件库/ CSS 框架、Controller→Service→Repository 单向依赖且 Controller 不碰 Repository、前端请求集中到独立 API 模块、端口不变、破坏性操作用自定义确认弹层。
- 状态：**FINAL（工程纪律）**。

## 最终决议速查（发生冲突时以此为唯一口径）

1. **建模**：独立多对多成员关系；禁止 `albumName` 逗号分隔、禁止 `Picture.albumId` 单外键、禁止复制图片记录。（CL-2/3/4）
2. **数据安全**：删相册 / 移出图片绝不删图片；仅图库删图物理删除。（HD-1 / CL-7）
3. **封面**：手动封面须为成员；无手动封面用"最近加入"；移出/删图后自动回退；空相册无封面。（CL-5）
4. **排序**：相册内持久化排序；新图默认置顶；跨相册独立。（CL-5）
5. **批量**：幂等忽略重复项；无效项走部分成功（failed 逐项说明）；相册不存在才整单失败；禁止全有或全无。（CL-6）
6. **相册名**：允许重名，后端不因重名拒绝。（CL-4）
7. **工程**：Java 8、无新前端组件库/框架、分层单向且 Controller 不碰 Repository、前端请求集中 API 模块、端口 4140/8140/33060 不变、自定义确认弹层。（CL-8 / HD-4）
