# 04 · 工程与架构规范

> 本文的所有条目为**长期工程纪律**，效力覆盖相册项目的每一次改动、每一轮迭代。即使后续需求描述中不再重复，这些规范默认继续生效。

## 1. 技术栈纪律

- **后端**：Spring Boot 2.7，运行于 **Java 8（JDK 1.8）**。
  - 必须保证在 Java 8 下可编译、可运行。
  - 禁止使用 Java 9+ 才有的语法 / API，例如：`var` 局部变量类型推断、`List.of / Map.of` 等不可变工厂、`Optional.isEmpty()`、`Stream.toList()`、文本块（text block）、`switch` 表达式等。集合初始化、空判断请用 Java 8 兼容写法。
  - 新增依赖需克制：优先复用已有依赖或手写工具方法，不为小功能引入重型库。
- **数据库**：MySQL 8。相册与成员关系的表结构变更，可使用 JPA `ddl-auto`，但必须在交付说明中写清新增表 / 字段及其含义。
- **前端**：Vue 3（Composition API + `<script setup>`）+ Vite。
  - 样式**只允许**沿用现有 **WindiCSS + 原生 CSS**。
  - **禁止新增任何 Vue 组件库**（Element Plus、Ant Design Vue、Naive UI、Vuetify、Arco 等），也**禁止引入其它 CSS/原子化框架**（Tailwind、UnoCSS、Bootstrap 等）。相册相关 UI（弹层、确认框、标签、排序交互等）需用现有技术手写。
  - 破坏性操作的确认框必须是**自定义弹层**，禁止 `window.confirm` / `alert` / `prompt`。

## 2. 后端分层约定

严格保持现有分层与单向依赖：

```
Controller  →  Service  →  Repository
```

- **Controller**：只负责接收请求、参数绑定、调用 Service、包装响应。**禁止**在 Controller 内直接注入或调用 Repository，**禁止**在 Controller 内写 SQL / JPQL / 业务规则。
- **Service**：承载全部业务规则与校验——相册增删改查、成员关系维护、封面计算与回退、排序、批量的部分成功逻辑、文件相关操作，都在 Service（或其协作类）内完成。
- **Repository**：只做数据访问。
- 新增的相册相关类应遵循现有包结构（`entity` / `repository` / `service` / `controller`）分别归位。

## 3. 前端组织约定

- 所有对后端的 HTTP 请求必须**收敛到独立的 API 模块**（例如 `src/api/album.js`、`src/api/picture.js`），统一在此创建/配置请求实例、定义各接口函数。
- `.vue` 组件中**禁止出现裸的 `axios.*` 调用**；组件只从 API 模块 import 函数来用。
- 现有 `App.vue` 中已有的请求如需复用，可一并抽取到 API 模块，但不要破坏现有上传/列表/删除功能。
- 组件划分保持清晰：相册列表、相册详情、批量操作工具条等应是可维护的组件，而非全部堆进单文件。

## 4. 端口与部署（呼应 HD-4）

相册项目为增量迭代，**对外端口保持不变**：

| 服务 | 端口 |
|------|------|
| 前端 | 4140 |
| 后端 API | 8140 |
| MySQL（对外映射） | 33060 |

- 不得为相册功能改动上述端口。
- 继续通过现有 `docker-compose` 编排；新增能力不应破坏"一键启动"。
- 前端经由现有 nginx / vite 代理访问后端，沿用现有 `/api` 前缀。

## 5. 交付纪律

每一轮改动的回复都应包含：

1. **本轮改动 / 新增的文件清单**（路径）。
2. **受影响或新增的接口一览**（方法、路径、请求 / 响应要点）。
3. **数据库变化说明**（如有）。
4. **验证结果**（构建 / 运行 / 简单自测）。
5. 一句**合规声明**：确认端口、技术栈（Java 8、无新组件库）、分层（Controller 不碰 Repository）、前端请求集中在 API 模块等纪律未被破坏。

## 6. 兼容与回归底线

- 不破坏现有主流程：上传、图库列表、下载、单图删除必须始终可用。
- 相册相关的任何"删除 / 移出"都不得危及图片文件与图片记录（HD-1 是最高红线）。
- 每轮新增功能都以前几轮产出的数据结构、接口、命名为基线，保持一致，不重复造字段、不复制记录绕过多对多关系。
